# 本地多存档系统

1.0.14 引入普通模式三存档及 Roguelike 预留栏位；1.1.0 开发版实现独立的 Roguelike 三旅程存储。主页面 → 开始游戏 → 选择模式 → 选择存档 / 旅程。普通模式选择空栏位开始新游戏，选择已有栏位继续进度；Roguelike 明确点击“点燃第一堆火”才建立旅程。

项目为纯 AI 实现的移植与改造，上游代码及资源保留原作者署名与 MPL-2.0 许可。

## 玩家可见行为

- 普通模式卡片显示编号、摘要与保存时间；Roguelike 显示种子、天数、回合与结束状态。
- 游戏菜单显示当前模式与编号，自动保存、导入、文件恢复和重新开始均作用于当前栏位。
- 每个非空栏位有删除入口，二次确认后删除；取消保持原样。
- 升级时保留旧进度，首次打开存档选择或直接进入游戏时迁移到普通模式的存档 1。
- 备份文件 / 存档代码只包含当前栏位。卸载前需要分别备份希望保留的各个普通模式存档。
- 普通模式字号使用原来的全局偏好；Roguelike 字号与主题保存在独立偏好中，首次仅只读继承普通设置。速度、援助和游戏进度绑定各自栏位。

## 存储与迁移

`android/web/save-slots.js` 同时由主页面、游戏与许可页加载。所有数据保留在应用原来的虚拟 HTTPS 来源下，不使用网络服务。

| 存储键 | 用途 |
| --- | --- |
| `adr.saveSlots.v1` | 普通模式权威数据库，版本、当前选择与三个普通栏位；仍保留 1.0.14 的 Rogue 预留元数据，1.1.0 不将其当作旅程 |
| `gameState` | 原作使用的当前栏位兼容缓存，方便沿用上游载入与导出流程 |
| `offlineFontSize` | 普通模式全局字号偏好 |
| `rogueSlot0` / `rogueSlot1` / `rogueSlot2` | 三个独立 Rogue Save JSON，每次有效行动后保存 |
| `rogueIndex` | Rogue 摘要索引；显示时优先校验各槽的实际存档 |
| `rogueBlueprints` | 跨 Rogue 旅程保留的图纸 |
| `roguePreferences` | Rogue 日夜主题与字号 |

数据库尚不存在但 `gameState` 存在时，将原字符串完整放入普通模式存档 1，并先成功保存数据库，才允许载入其他栏位。异常字符串也会原样保存，列表标为“存档异常”，不会把它静默当作新游戏覆盖。

数据库存在后，兼容缓存不会被重新当作旧存档迁移。删除当前栏位会清除其缓存，即使缓存清理因存储故障失败，下次进入也会以数据库为准，避免已删除进度重新出现。

## 保存、切换和恢复

普通游戏页面启动时确定自己的模式与编号，之后始终保存到这个绑定栏位。即使另一个页面改了当前选择，旧页面保存也不能写入新栏位。进入普通游戏前根据所选栏位恢复兼容缓存，空栏位则清除缓存，不借用其他栏位的进度。以下普通模式的缓存切换逻辑不用于 Rogue。

保存时将整个栏位数据库作为一个 localStorage 值原子替换，写入成功后再同步兼容缓存。失败会保留最后一次成功写入的数据库；游戏显示保存失败提示。其他栏位的数据不会先被删除再重写。

Base64 导入和 Android 文件恢复写入选中栏位，再重载游戏；替换前暂停旧页面的离开保存，避免旧内存状态覆盖新进度。主页的原生恢复入口先进入“选择恢复位置”，选择非空栏位时确认覆盖，再打开系统文件选择器；原生格式检查后还会确认一次恢复。

“重新开始”只更新当前栏位，并沿用上游的前代继承数据规则。适配层不调用原作的 `localStorage.clear()`，因此保留其他栏位、Roguelike 旅程和全局偏好。

## Roguelike 的独立边界

`?mode=rogue` 只调用 `Rogue.boot()`，跳过普通 `Engine.init()` 和移动适配层的普通存档初始化。`rogueSlotN` 是权威数据，URL 中的 `slot=N` 只用于刷新继续所选旅程。Rogue 进入、行动、保存、后台、刷新与返回均不写 `gameState` 或 `adr.saveSlots.v1`。

每次行动后保存整个旅程，包括 RNG、队伍补给、迷雾、地牢位置和战斗回合。保存 slot / index / 共享图纸时遇到配额异常，会尝试回滚已写入的键并显示提示；不会抛出控制台异常。损坏或不兼容的旅程保留原始字符串，阻止读取；可确认删除该槽，其余槽不受影响。

Android 的 Rogue 备份以 UTF-8 JSON 的 Base64 写入带 `rogue` 的 `.adr.txt`。恢复前使用 Rogue 校验器并弹出中文确认；取消不变，确认只替换当前 Rogue 槽，即使源文件来自不同槽。普通模式和 Rogue 的备份互不兼容。图纸跨旅程保留，恢复或删除一段旅程不会清除已经发现的图纸。源码与玩法见 [ROGUELIKE.md](../docs/ROGUELIKE.md)。

## 异常与范围

- 存档数据库版本或结构无法识别时停止载入，显示错误并保留原始字符串。
- 单栏位的 JSON 损坏时阻止进入该栏位，其他正常栏位仍可使用。删除损坏栏位同样需要确认。
- 写入失败不会保证本次尚未保存的内存进度已持久化；最后一次成功保存的进度仍在。
- 该系统是本机多栏位存储，没有云同步。卸载、清除应用数据或丢失设备会影响所有栏位。
- 不支持把旧版 APK 的单存档系统直接当成多栏位管理器；回退旧版前应先逐个导出需要的进度。
