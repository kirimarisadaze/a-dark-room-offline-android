# 本地多存档系统

1.0.14 起，普通模式与 Roguelike 模式各有 3 个独立栏位。主页面 → 开始游戏 → 选择模式 → 选择存档。普通模式选择空栏位开始新游戏，选择已有栏位继续进度；Roguelike 目前只记录预留栏位，玩法仍待实现。

项目为纯 AI 实现的移植与改造，上游代码及资源保留原作者署名与 MPL-2.0 许可。

## 玩家可见行为

- 卡片显示存档编号、进度摘要和最近成功保存时间。
- 游戏菜单显示当前模式与编号，自动保存、导入、文件恢复和重新开始均作用于当前栏位。
- 每个非空栏位有删除入口，二次确认后删除；取消保持原样。
- 升级时保留旧进度，首次打开存档选择或直接进入游戏时迁移到普通模式的存档 1。
- 备份文件 / 存档代码只包含当前栏位。卸载前需要分别备份希望保留的各个普通模式存档。
- 字号是全局偏好；速度、作弊和游戏内设置保存在各栏位的游戏状态中。

## 存储与迁移

`android/web/save-slots.js` 同时由主页面、游戏与许可页加载。所有数据保留在应用原来的虚拟 HTTPS 来源下，不使用网络服务。

| 存储键 | 用途 |
| --- | --- |
| `adr.saveSlots.v1` | 权威存档数据库，版本、当前选择、两个模式的 3 个栏位及元数据 |
| `gameState` | 原作使用的当前栏位兼容缓存，方便沿用上游载入与导出流程 |
| `offlineFontSize` | 全局字号偏好 |

数据库尚不存在但 `gameState` 存在时，将原字符串完整放入普通模式存档 1，并先成功保存数据库，才允许载入其他栏位。异常字符串也会原样保存，列表标为“存档异常”，不会把它静默当作新游戏覆盖。

数据库存在后，兼容缓存不会被重新当作旧存档迁移。删除当前栏位会清除其缓存，即使缓存清理因存储故障失败，下次进入也会以数据库为准，避免已删除进度重新出现。

## 保存、切换和恢复

游戏页面启动时确定自己的模式与编号，之后始终保存到这个绑定栏位。即使另一个页面改了当前选择，旧页面保存也不能写入新栏位。进入游戏前根据所选栏位恢复兼容缓存，空栏位则清除缓存，不借用其他栏位的进度。

保存时将整个栏位数据库作为一个 localStorage 值原子替换，写入成功后再同步兼容缓存。失败会保留最后一次成功写入的数据库；游戏显示保存失败提示。其他栏位的数据不会先被删除再重写。

Base64 导入和 Android 文件恢复写入选中栏位，再重载游戏；替换前暂停旧页面的离开保存，避免旧内存状态覆盖新进度。主页的原生恢复入口先进入“选择恢复位置”，选择非空栏位时确认覆盖，再打开系统文件选择器；原生格式检查后还会确认一次恢复。

“重新开始”只更新当前栏位，并沿用上游的前代继承数据规则。适配层不调用原作的 `localStorage.clear()`，因此保留其他栏位、Roguelike 预留状态和全局偏好。

## 异常与范围

- 存档数据库版本或结构无法识别时停止载入，显示错误并保留原始字符串。
- 单栏位的 JSON 损坏时阻止进入该栏位，其他正常栏位仍可使用。删除损坏栏位同样需要确认。
- 写入失败不会保证本次尚未保存的内存进度已持久化；最后一次成功保存的进度仍在。
- 该系统是本机多栏位存储，没有云同步。卸载、清除应用数据或丢失设备会影响所有栏位。
- 不支持把旧版 APK 的单存档系统直接当成多栏位管理器；回退旧版前应先逐个导出需要的进度。
