# 新手体验核查与任务划分

依据用户提供的《新手体验与可改动项清单》，以当前代码和实际检查核对诊断。该清单包含体验反馈、推断与建议配方；建议中的数值不直接视为已经确认的新规则。

## 本任务：引导与补给反馈

任务分支为 `codex/survival-onboarding`，基于 `c8e324b`。目标是让玩家知道下一步做什么、当前补给是否耗尽，以及已知回营路线还需多少水。保持 v3 存档与现有经济、地形、战斗和随机流。

- A4：新局记一条明确行动提示；初期据点直接显示“下一步”，目标页展示实际仓库材料，并可直接打开长矛、水袋、工坊对应分类。
- A5：首次建工坊追加后续制造提示；水袋制成后明确提醒整备补给，避免把容量增加误认为自动装满。
- B2：探索与队伍页显示已知最省水回营耗水及全队含备用水，短缺时用颜色与文字提示，未知道路单独说明。只计算已探索地形与打通出口，包含地牢撤离耗水；不承诺涵盖遭遇战或额外绕路。
- C1：当前饮水与口粮低于 25% 显示“偏低”，归零显示“耗尽”，并分别记录日志。刷新和阅读不重记，补充后可重新触发。备用物资需主动使用；回程提醒开关不关闭基础耗尽提示，深渊跳过补给警报。
- C3、D3：保留实际缺料反馈、整备无变化时禁用、采集物自动入仓及原有存取边界。

`NUM.SUPPLY_WARNING_RATIO = 0.25` 仅决定提示阈值，不影响消耗、伤害、产出、初始资源、容量或地图。新持久字段仅为 `save.flags.supplyLevels` 和 `save.flags.workshopGuide`，缺字段的旧 v3 档在内存补默认值；原始槽位不因读取重写。

## 对其余建议的核查

| 项目 | 当前事实 | 本次处理 / 后续任务 |
| --- | --- | --- |
| A1 自适应开局补给 | 初始据点附近会尝试布置资源点；候选冲突可能使部分站点回退到较远位置。并非所有资源点都是任意远的随机出生。 | 保留初始补给；另立开局可达性与补给任务，结合实际地形、未探索路线、整备备用水和遭遇验证，不把抽查当作任意种子保证。 |
| A2 初始探索半径 | 当前基础饮水 10；在据点可直接整备并携带基础备用水目标 20，需在队伍页主动使用。 | 不直接同时增加初水和降低地形成本。下一数值任务先比较一种方案，并分别记录开局体验与完整通关指标。 |
| A3 提前食物压力 | 60 食物与 3 人口是当前初值；人口、菜圃、生产、过夜与行动过程会改变实际压力。 | 降初始食物和提高人口消耗是两项参数，须分开试验。不能通过日志强行满足“100 回合内饥饿”代替真实规则。 |
| B1 水袋过晚 | 水袋已经不需要工坊，成本为 5 木 / 4 皮毛。“改为 10 木 / 2 皮毛”会提高木材需求。 | 修引导，不增加工坊前置；原配方和一次性锁定保留。材料调整另评估。 |
| B3 自动寻路 | 已发现地点可选中后“沿路前往”，每次最多 12 步，遇到战斗 / 际遇即停。 | 保留确认式行走，避免误触地图消耗回合；目标页可直接选中已发现的猎场。现有按钮减少多少点击仍需专门测量，未声称达到 60%。 |
| C2 采集变化 | 手动资源点的基础收益固定，野外移动另有群系事件。 | 作为单独内容任务评估三种方案之一；不能一次加入多套机制，也不在提示任务中改变随机序列。 |
| D1 手动与生产比例 | 林地基础手采 6、单工人 0.18 / 回合，单看基础比值约 33.3；运输、往返、研究与生产并行会影响整体效率。 | 同一经济任务逐项调整并跑模型通关；不能把工人乘 3 与手采降至 2 一起改。 |
| D2 每站人数上限 | 当前主要限制为据点可派人口，没有清单提出的每站 3 人上限。 | 单独评估新建站需求、旧档超额人手处理、人口不足与运输；本次不驱逐现有工人。 |
| E1 地牢内容占比 | 当前有限地牢有单层目标，尺寸按深度档位选择；多层会改变补给、战斗和撤离成本。 | 结构任务，先定义层数、目标奖励、续战和旧档契约，再做通关占比评估。 |
| E2 飞船与资源溢出 | 当前模块仍按既有配方制造，没有新增充能阶段。 | 配方调整和充能是不同任务；不得只加重复等待凑时长。需要同时记录终局库存与可理解的操作流程。 |
| E3 诚实探索基准 | 既有完整按钮通关没有注入资源，但规划可只读完整地形；这不等于只利用玩家已知信息。 | 后续规划器限制为已探索图、可见线索与未知边界，补给也只依赖已知位置；分别报告其结果和现有全图规划基线，不据单局真人数据直接推算 4 倍时长。 |

## 已做核查与范围限制

`scripts/test-rogue-onboarding.mjs` 的只读地形抽查覆盖 seed 0–999：最近资源点均为 3 步，所有资源点可达，但最远资源点达到 43 步，说明回退位置确实值得单独验证。仅计算地形往返时，初始 10 水在最不利群系返回最近点后剩 1，因此**未满足原清单提出的“初水往返后至少余 3”**。现有整备备用水提供额外缓冲；本抽查不包含遭遇、战斗和玩家对未知地形的判断，不能证明所有新局都安全。

本次模型完整流程仍为 5345 回合（包含通关后深渊测试），没有改变经济。它不是已经达成 `AGENTS.md` 2500–3500 回合、地牢占比至少 15%、铁 / 水库存及点击数门槛的证据。后续数值任务应先统一“飞船结局”与“额外深渊测试”的统计边界，再逐项记录与回滚，不掩盖当前基线超标。

## 验证与交接

必须使用当前分支生成的 Android 静态资源运行，不能复用发行版的历史结果：

```powershell
python scripts/prepare-android-assets.py
node scripts/test-rogue.mjs
node scripts/test-rogue-issues.mjs
node scripts/test-rogue-storage.mjs
node scripts/test-rogue-onboarding.mjs
node scripts/test-rogue-ui.mjs
node scripts/test-rogue-storage-ui.mjs
node scripts/test-rogue-survival-ui.mjs
node scripts/test-rogue-playthrough-ui.mjs
```

UI 测试使用工作机已有 Playwright，通过 `PLAYWRIGHT_MODULE` 指定路径，不添加游戏运行依赖。专项测试涵盖真实新局的目标导航、声明材料夹具的水袋制造、声明地形夹具的回程与补给边界，以及五种尺寸 / 两种主题 / 大字。完整按钮测试另从新局开始，推进只点真实控件，规划仅只读状态，不注入资源、生命、迷雾或图纸。两类验证不可混称为同一次新手实玩。

普通模式两份存档检查原始字符串；控制台、缺译、缺失资源与外部请求分别检查。报告应附实际命令摘要和完整按钮通关的结果；未连接 Android 设备时，不能声称已做真机验证。

本任务结果见 [验证记录](QA-SURVIVAL-ONBOARDING.md)，其中包含实际命令、输出摘录与通关边界。

本任务走独立 PR；没有单独提高版本号、签发 APK 或覆盖既有 Release。协作文档任务另在 PR #1，两个任务独立审核后再集成发布。
