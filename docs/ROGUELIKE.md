# 废土余火 · Roguelike 模式

版本：**1.1.0 / versionCode 16**，[GitHub Release](https://github.com/kirimarisadaze/a-dark-room-offline-android/releases/tag/v1.1.0)。基于用户提供的《小黑屋 Roguelike 实现规格 v1.0》实现完整可玩旅程；按后续授权补全配方、研究、事件与必要的主页和 Android 集成。原作 A Dark Room 由 Michael Townsend / doublespeak games 及贡献者创作，原作署名、源码及第三方许可保留。新增源码采用 MPL-2.0。

## 开始与操作

从主页面选择“开始游戏 → Roguelike 模式”，选择三段旅程之一。可以输入 0–4294967295 的整数种子，也可以留空随机生成。只有点击“点燃第一堆火”才创建新存档。已有旅程直接继续，刷新恢复当前旅程和战斗。

手机底部切换探索、据点、队伍；宽度 1100px 起同时显示三栏。日间使用白底，夜间沿用当前项目的 `#272823` 背景；正文沿用原版文字风格，地图专用等宽字体，细线、直角、无阴影。菜单可调 16–22px 字号、主题和过夜速度。字号和主题独立保存，首次只读继承普通模式设置。

点击屏幕方向键或使用方向键 / WASD 行走；空格休息，Esc 按层级返回。地图以 `@` 为中心显示 15×15 窗口，空白是未知、暗色是记忆、明亮是视野。`B` 是据点，`+` 是区域出口，`D` 是地牢，`!` 是威胁。完整图例可随时查看。

每次有效行动推进回合。打开面板、查看材料、阅读手记和设置界面不消耗回合。一次过夜按所选速度推进 25 / 50 / 100 回合；没有后台计时或离线收益。选定已发现的地点后，“沿路前往”最多执行 12 次真实移动，遇战或结束立即停止。

## 一段可通关的旅程

1. 在火堆旁收集周围物资，制造长矛，去附近林地、猎场采集。采集进背包，回据点存入共享仓库；占领站点后可派村民每回合生产。
2. 制作水袋、背包与护甲，建造工坊和水井。补给按钮带上水、口粮及备用物资；远途在队伍面板使用备用水与口粮。材料操作会显示缺口。
3. 探索九片区域。清理威胁后可建立更多据点，最多三处；据点共用仓库，距离影响运输损耗，修路可降低损耗。
4. 招募最多两位同行者，研究 24 项技术。战斗中选择目标后攻击、防御反击、闪避反击、治疗或逃跑；同行者自动攻击，普通旅程中死亡会永久移除并留下纪念。
5. 从旧档案库、铸造厂、反应堆取得船体、推进器、能量核心图纸，回据点制造模块，再前往第九区域的飞船残骸组装并离开。其他地牢提供水罐、武器或可继续挑战的储藏库。
6. 飞船通关后解锁深渊，只记录最深层数，不产出经济资源。深渊暂停聚落经济、保留进入前队伍快照；撤离或死亡会恢复物资与队伍，不损失正式旅程进度。

队伍死亡或全部据点人口归零会结束本局。发现的图纸跨旅程保留。可从菜单主动启用一批“旅途援助”，使用后本局永久标记；正常通关不需要援助。

## 独立存档与 Android

| 键 | 用途 |
| --- | --- |
| `rogueSlot0` / `rogueSlot1` / `rogueSlot2` | 三个完整 Save JSON |
| `rogueIndex` | 旅程摘要索引 |
| `rogueBlueprints` | 跨旅程图纸 |
| `roguePreferences` | Rogue 日夜主题和字号 |

每次有效行动保存，包括 RNG、迷雾、地牢、战斗回合和敌方生命。损坏存档阻止进入但保留原始数据；删除必须确认。写入失败显示提示并尝试回滚已经写入的键。

Rogue 不初始化普通 `Engine`、`StateManager` 或音频，不写 `localStorage.gameState`、普通多存档数据库和普通设置。正常模式仍由原入口初始化。普通 `world.js`、`room.js`、`path.js`、`events.js` 和 `state_manager.js` 保持原样；`engine.js` 只替换末尾启动分流，`index.html` 只追加脚本和 CSS。

Android 适配层在 Rogue 入口提前分流。前后台与返回操作只保存当前 Rogue 槽；倾斜传感器不会控制字符地图。系统菜单或游戏菜单可备份 / 恢复当前旅程，备份名带 `rogue`，内容为 UTF-8 JSON 的 Base64。恢复走 Rogue 校验器与中文确认，只替换当前槽。两种模式的备份互不兼容。切换设备需要分别备份每段希望保留的旅程。

## 文件与扩充数值

全部运行时代码为普通 `<script>` 加载的原生 JavaScript，没有模块、第三方运行依赖或构建步骤，不使用定时器推进模拟。玩家中文文案集中在 `script/rogue/lang/zh.js`，`Rogue.t(key)` 缺 key 返回 `!!key!!`。

| `script/rogue/rogue.js` | 启动、卸载、Android 生命周期与备份 |
| `rogue.state.js` / `rogue.num.js` | 状态、种子随机、行动、推进、全局常量 |

规格已有全局数值、火焰等级、敌人深度倍率和损耗公式保留。为补全可玩链路，新增初始仓库（35 木、20 石、60 食物、30 水）、三名村民、水袋 40 / 水罐 80 容量、背包 80 / 升级 140 负重，以及装备、建筑、研究、事件、船体三模块配方。全局平衡常量集中在 `rogue.num.js`，实体配方、属性与研究效果集中在对应 content 表。

## 规格中需要协调的定义

- 区域图的“3×3、中心起点、恰好阻断两边、唯一 1–9 难度且所有可通行邻边难度差不超过 2”不能同时满足。采用文档不变式允许的 **三条初始阻断边**，从 12 组满足连通、BFS 层序和通行难度约束的布局中按种子选择；约束作用于可通行边，栈道可在游戏中解除相应阻断。不能将这一实现描述为逐字执行“两条阻断”的算法。
- 边界全墙与“走到边界跨区”冲突。出口放在边界内缩一格的 `+`，再向外行动跨区，边界行列仍全是墙，站点不在边界。
- `flags` 不仅保存 boolean，还保存日志、RNG、纪念、当前战斗、地牢与深渊快照，使中断后能精确恢复；FloorState 增加运行时需要的尺寸字段。
- 可重复地牢使用 `>` 作为下一层目标，抵达后允许下潜。深渊只记录深度，其他储藏库按表提供奖励。
- 规格未定义的完整配方链、24 项研究、事件按用户后续“完整可玩、内容可创新、自行解决”的授权补齐。寒冷、感染、辐射没有额外独立状态机制；当前生存消耗包含饥饿和干渴。

## 验证方法与结果

```powershell
python scripts/prepare-android-assets.py
node scripts/test-rogue.mjs --playthrough
node scripts/test-rogue-ui.mjs --soak
node scripts/test-home.mjs
node scripts/test-save-slots.mjs
node scripts/test-offline.mjs --smallest-only
.\build-android.ps1
```

纯逻辑测试不需依赖。浏览器测试需已有 Node.js、Playwright Chromium，可用 `PLAYWRIGHT_MODULE` 指定包目录；测试工具不是游戏运行依赖。界面脚本缺少结局快照时会先运行完整行动测试来生成，输出位于 `.local/rogue-tests/`。不加 `--soak` 可跳过额外十分钟检查。

本次自动化覆盖：

- T1–T3：seed 42 三次九区域一致、同种子同 100 次行动的完整存档 hash 一致、存档读写 JSON 原始字节一致。
- T4：逻辑层 600 次行动隔离，浏览器额外十分钟真实行动、刷新与返回后，普通存档和数据库字节保持一致。
- T5–T6：一万个区域图种子满足采用的连通与难度不变式，额外 100 个种子的全部九区域共 900 张地图检查边界、全体非墙可达、站点唯一且可达。
- T7–T10：共享仓库、饥饿人口不为负、战斗回合与 RNG 恢复、截断档保留；另外检查存储配额失败回滚和缺译标记。
- 合法行动完整通关：自动玩家读取地形规划路径，但不改资源、HP、状态或迷雾，不开援助；完成九区域、有限目标、图纸、制造、飞船结局、深渊第二层与撤离，共约 2051 回合。
- 真实 UI：采集、制造、占领派人、刷新续战、回主页续普通进度、备份与取消 / 确认恢复、损坏档删除保护、结局与深渊、模态焦点循环。
- 八组尺寸 / 主题组合：320×512、360×740、412×915、1440×900，日夜各一；三面板、菜单、战斗无横向溢出，按钮至少 44px，320px 下使用 22px 字号。离线页面没有脚本报错、控制台警告、缺失资源或外网请求。
- 普通主页 9 项 / 24 组布局、多存档 14 项和最窄屏普通模式综合回归；APK 编译、资源打包、版本、路径、对齐、原签名及无联网权限验证。

这些检查不能替代真人长期游玩和平衡评估。**尚未完成真机安装、系统文件选择器及实际 Android WebView 图形交互验证；3–8 小时的真人通关时长也未确认。** 当前没有连接的 Android 设备；已有 ARM 模拟器存在历史 GPU / EGL 初始化故障，不把旧版原生测试结果当成本版真机验证。
